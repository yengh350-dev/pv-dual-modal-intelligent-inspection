# 场景联动与无人机匹配说明

## 本次实现

- 每个巡检任务拥有独立的场站、区域、底图、经纬度、比例尺、计划航线、已飞航迹、无人机、载荷、天气和遥测参数。
- 切换任务后，地图底图、航线形状、无人机编号、电量、高度、速度、信号、RTK 状态和环境指标同时更新。
- 地图上的无人机沿当前任务的实际航迹移动，扫描扇区表达双光载荷当前覆盖方向。
- “重新匹配”提供设备发现、链路握手和匹配成功三个可见阶段；匹配结果同时进入设备状态和诊断入口。
- 所有生成式场站底图均在界面标记为“概念演示底图”，不能作为真实现场证据。

## 接入真实设备时的数据对应关系

| 界面状态 | 真实数据来源 | 建议更新方式 |
| --- | --- | --- |
| 无人机位置与朝向 | 厂商 SDK 遥测中的经纬度、航向角、时间戳 | WebSocket 或 SSE，建议 2-10 Hz |
| 已飞航迹 | 带时间戳的 GNSS/RTK 轨迹点 | 按任务追加，断线后按序号补传 |
| 计划航线 | KML/KMZ、厂商任务文件或规划服务 | 任务创建后冻结版本 |
| 匹配状态 | 设备发现、身份校验、心跳、图传和载荷握手 | 后端状态机统一判定 |
| RGB/Thermal 状态 | 相机工作模式、拍照计数、热像标定与时间同步 | 遥测持续更新，异常立即告警 |
| 电量与返航余量 | 智能电池、功耗、风速、返航距离 | 由飞控提供主值，平台只做提示 |
| 场站底图 | 正射影像、瓦片地图或合规卫星图服务 | 按场站版本和采集日期管理 |

## 匹配状态机建议

1. `discovering`：发现遥控站或边缘网关，尚未确认设备身份。
2. `authenticating`：校验设备序列号、证书、任务绑定和时间同步。
3. `linking`：分别建立遥测、图传与载荷数据链。
4. `ready`：三链路满足阈值，可以进入只读监看和数据接收。
5. `degraded`：部分链路可用，界面必须明确指出受影响能力。
6. `offline`：停止刷新实时值，保留最后同步时刻并启用本地缓存。

平台当前使用演示状态机，不向无人机发送飞行控制命令。真实部署时，飞行安全判断、返航、悬停和降落仍由厂商地面站、遥控器和持证飞手负责。
