# 异常与工单工作流升级

本轮直接修改桌面上的平台系统_完整版，不以旧工作区副本作为运行版本。

## 参考与取舍

- Ant Design 列表页规范：https://ant.design/docs/spec/research-list/
  采用扫描优先、筛选靠近数据、列表进入详情的结构。
- ProComponents Table 文档：https://github.com/ant-design/pro-components/blob/master/site/components/table.md
  采用明确选择范围和批量操作反馈；不提供未经复核的批量派单。
- DJI FlightHub 2 数据管理：https://fh.dji.com/user-manual/en/organization-management/data-management.html
  借鉴任务、影像、事件上下文关联，保留证据来源和演示边界。

未复制第三方项目代码，也未将第三方功能描述作为本平台已实现能力。

## 已实现

- 异常中心和工单改为 API 数据源；连接失败不以本地样例冒充已保存记录。
- 列表/看板、状态筛选、搜索、逾期筛选、CSV 导出与详情链接。
- 异常人工复核、带说明的复飞/排除操作及批量部分失败反馈。
- 已确认异常创建关联工单；已有在办工单进入已有记录，避免重复处置。
- 新建表单保存实际标题、负责人、验收人、截止时间、处置要求和初始阶段。
- 四项处置清单、现场记录、结论、提交验收、退回、取消和关闭。
- 后端禁止越级流转；验收需完整清单、结论和不同的验收负责人名称。
- 修订号冲突返回 409，编辑不会静默覆盖；关闭编辑和重新读取有丢弃提醒。
- 处置记录与审计在同一事务保存。旧工单缺少的记录不伪造。
- UTC 存储及明确时区返回，本地截止时间不偏移。
- 侧边栏异常数量使用同一份 API 查询；不再固定显示 37。
- 语义化蓝/青/琥珀/红配色；深浅色对比及移动端局部表格滚动。

## 尚未完成的生产能力

其他页面仍有明确标注的演示任务与影像，本轮不是全部业务的真实设备联调。
影像配对展示不证明真实 RGB-T 标定。商业大模型仍需服务端有效凭据。
验收负责人目前为名称字段，尚未接入实名人员目录与逐人验收签署权限。
附件上传、审批会签、人员通知、企业组织隔离和并发重复派单的数据库级唯一约束
仍需后续实现与独立验证，不能据此宣称整个 OA 或平台已生产验收。
