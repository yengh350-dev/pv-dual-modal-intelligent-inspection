# 无人机接入手册

## 先说结论

无人机不是用一根“平台专用线”接入。最通用的做法是：无人机采集 RGB、热红外、时间和位置数据，飞行结束后由遥控器、SD 卡、厂商云或地面站导出任务包，再由平台校验、上传、配对、分析和复核。

平台默认是证据与运维系统，不是飞控系统。起飞、返航、避障、失联处置仍由合规飞控和现场飞手负责。

## 方案 A：任务包导入，推荐本科项目先做

1. 使用具备 RGB 与热红外传感器的无人机或载荷完成航线采集。
2. 导出 RGB 文件、Thermal 文件、SRT/CSV/厂商元数据和任务说明。
3. 生成 `manifest.json`，每个 `pairId` 对应同一时刻附近的一张 RGB 和一张 Thermal。
4. 运行插件校验：

```bash
python3 plugins/pv-rgbt-ingestion/scripts/validate_manifest.py \
  plugins/pv-rgbt-ingestion/assets/sample-manifest.json
```

5. 调用 `POST /api/v1/ingestion/manifests/validate` 做服务端校验。
6. 通过后把文件上传对象存储，再启动解码、温度读取、配准、检测和报告流水线。

该方案不依赖某一家无人机厂商，易复现、易调试，也适合论文实验留档。

## 方案 B：地面站或厂商云适配器

在适配器服务中完成：OAuth/API Key 管理、任务同步、媒体下载、遥测字段映射、断点续传、限流和重试。适配器只把标准化数据写入平台，不把厂商字段扩散到核心业务表。

建议标准事件：`mission.created`、`mission.uploaded`、`ingestion.validated`、`analysis.completed`。生产 Webhook 需要 HMAC-SHA256 签名和重放保护。

## 任务包结构

```text
MSN-20260905-001/
  manifest.json
  RGB/
    PAIR-0001.jpg
  THERMAL/
    PAIR-0001.jpg
  telemetry/
    flight.srt
  calibration/
    radiometric.json
```

必须保存：相机/载荷型号、焦距、发射率、反射温度、环境温湿度、飞行高度、云量、风速、时间同步方式和软件版本。不同厂商热图可能只是伪彩 JPEG，也可能包含可测温数据，二者不能混用。

## RGB-Thermal 配对与配准

- 首先用时间戳、帧序号和位姿做粗配对
- 再用相机内外参、单应性或特征匹配进行空间配准
- 保存原图、变换矩阵、重采样方法和配准质量分数
- 配准失败的帧进入隔离区，不直接交给缺陷模型
- 热异常要结合相对温差、跨帧持续性和环境反射复核

## 真正上线还缺什么

- 具体机型 SDK/云 API 凭据及法律许可
- 对象存储、消息队列、任务编排和 GPU 推理服务
- RTK/PPK 或地面控制点方案
- 热成像辐射测温标定与现场 SOP
- 断网续传、校验和、病毒扫描、数据脱敏和备份
- 无人机法规、禁飞区、人员资质、保险和现场安全制度
